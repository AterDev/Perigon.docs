# 10.0 Update Notes

## 10.0.1

This version mainly optimizes the internal implementation of the tool. There are no functional changes.

### Changes

The tool no longer uses `EFCore/Sqlite` internally and now uses `Perigon.minidb` instead. The results are as follows:

- Package size is reduced from 17 MB to 10 MB
- Entity parsing no longer depends on `EFCore DbContext`; it continues to use `Roslyn`, which improves generation speed

Also fixed incorrect documentation links.

### Impact

Because Sqlite is no longer used, you need to add your projects again after opening the tool. Data previously stored in Sqlite cannot continue to be used.

## 10.1.0

Added the `pack` and `install` commands to package and install modules, providing a basic foundation for cross-project module reuse.

> [!TIP]
> The latest templates no longer include default module code such as `SystemMod`. If you need these modules, you can get the module files from `package_modules` in the [template repository](https://github.com/AterDev/Perigon.Modules), and then install them through the command line.

## 10.1.9 - 10.1.10

- The publish workflow now validates tests before publishing and writes the local package to the repository-level `artifacts` directory.
- The `generate` command adds `entity`, `dto`, `manager`, and `controller` subcommands. `entity` prints entity-model generation rules, and `controller` supports the `api` alias.
- Entity-generation rules now clarify module-directory creation and the standard `DbSet` property form in `DbContext`.

## 10.1.11

- C# OpenAPI client generation now recognizes binary file fields in `multipart/form-data` and generates upload methods that accept a `Stream`, file name, and multipart field name.
- Multipart generation now supports multiple file fields and ordinary string, numeric, boolean, and array form fields across C#, Angular, and Axios clients.
- Fixed an extra-dot namespace issue in C# model generation when the project name is empty.

## 10.1.12

- The `generate request` command adds `-c/--cover-base-service`; existing `base.service.ts` content is preserved by default and is overwritten only when requested. Studio also preserves the file by default.
- Fixed URL composition in generated C# upload, multipart, download, and JSON requests so multi-level `HttpClient.BaseAddress` paths are preserved instead of resolving from the domain root.

## 10.1.13

- Fixed request service name generation when an OpenAPI tag contains spaces or other invalid identifier characters; generated C# and TypeScript service names now use safe PascalCase identifiers.
- Fixed request service filenames for OpenAPI tags containing spaces so they consistently use hyphenated names.

## 10.1.14

- Fixed Linux package publishing by tracking `ShareDlls.txt` with the casing expected by the pack script, preventing duplicate shared assemblies from being included in the Studio archive.

## 10.1.15

- Client request generation now supports OpenAPI 204, 205, 304, and HEAD no-content responses; C# generates `Task`, while Angular/Axios generate `void` return types.
- C# multipart and file-upload methods now use the HTTP method declared by OpenAPI, including `PUT`; Angular/Axios request method handling is aligned as well.
- C# clients preserve the raw error response through `ResponseContent`, including `Content`, `StatusCode`, and `ReasonPhrase`, so callers can handle different error formats outside the generated client.

## 10.1.16

- C# client request paths are now generated as relative URIs without a leading `/` and passed directly to `HttpClient` for merging with `BaseAddress`. When configuring a C# client, `BaseAddress` must end with `/`, for example `https://example.com/api/`.
